# 사이트 정보구조 (IA) 스펙 (v1, 2026-07-28)

> 근거: 사용자 지시(홈페이지 ≠ 랜딩페이지 분리) + MARKETING-PLAN §2 + THIRD-PLAN P0-7
> 소유 레인: `ui` (`app/(marketing)/**`, `components/marketing/**`)

## 0. 문제

현재 `/` 하나가 **기업 홈페이지 + 서비스 소개 + 사전등록 유도**를 전부 겸하고 있다. 광고 유입·검색 유입·지인 소개 유입이 전부 같은 긴 페이지에 떨어져, 각 유입의 다음 행동이 흐려진다.

## 1. 목표 구조

| 경로 | 역할 | 주 유입 | 성공 지표 |
|---|---|---|---|
| `/` | **홈페이지** — 회사·서비스의 얼굴. 무엇을 하는 곳인지 30초 안에. 과하게 팔지 않는다. | 검색·직접·명함·소개 | `/service` 이동률, 사전등록 CTA 클릭 |
| `/service` | **서비스 상세** — 제품 설명의 본진. 3단계·리포트 2종·안전 원칙·FAQ. | `/` 경유, 검색 | 사전등록 CTA 클릭 |
| `/preregister` | **사전등록 랜딩** — 단일 목적. 이탈 요소 최소. | 광고·SNS·설문 | 이메일 제출 전환율 |
| `/about` `/faq` `/terms` `/privacy` | 보조 (현행 유지) | — | — |
| `/login` `/app/**` | 실서비스 | — | — |

**핵심 원칙**: `/` 는 신뢰를, `/service` 는 이해를, `/preregister` 는 전환을 담당한다. 한 페이지가 둘을 겸하지 않는다.

## 2. 페이지별 구성

### `/` 홈페이지 (신설)
1. 히어로 — 브랜드 + 한 줄 가치 + [서비스 알아보기] / [사전등록] 2버튼. 이미지 1장.
2. 한 문단 소개 — "우리는 무엇을 하는 회사인가" 3줄.
3. **신뢰 4배지** (§3) — 홈에서 가장 중요한 블록.
4. 리포트 미리보기 2종 요약 (완료 / 확인 필요) → [자세히 보기 → /service]
5. 소식·문의 — 베타 상태 안내, 문의 이메일.
6. 푸터(SiteFooter, 119 고지 포함)

길게 쓰지 않는다. 스크롤 3~4화면.

### `/service` 서비스 상세 (현 `/` 콘텐츠 이관 + 심화)
1. 히어로(제품형) — 현 랜딩 히어로 카피 **수정본**(§4)
2. 이렇게 작동합니다 (3단계 — 현행 유지)
3. 앱이 아니라 진짜 전화입니다 (보호자/부모님 이중 수혜 — 현행 유지)
4. **리포트 미리보기 2종** — 완료 예시 + **"확인 필요" 예시**(신규). "억지로 판단하지 않습니다" 카피 동반.
5. **안전·신뢰 원칙 섹션**(신규) — 신뢰 4배지 확장판 + 119 고지 + AI 자기고지
6. FAQ (FaqSection — 신규 문답 §4-2 추가)
7. 마지막 CTA

### `/preregister` (정리)
- 현행 좌/우 분할 유지. 단, **이탈 링크 축소**: 좌측 브랜드 링크와 "← 서비스 소개로 돌아가기"는 `/service` 로 연결.
- 신뢰 4배지 축약형 1줄 추가(전환 직전 불안 해소).

## 3. 신뢰 4배지 (전 페이지 공통 컴포넌트 — `components/marketing/TrustBadges.tsx`)

MARKETING-PLAN §2 "모든 채널 필수 포함 신뢰 요소"를 화면 1급 요소로 승격한다. FAQ 안에 접어 두지 않는다.

| 배지 | 문구 |
|---|---|
| 본인 동의 후 발신 | "첫 통화에서 부모님께 직접 안내하고, 동의하신 뒤에만 전화드려요." |
| 녹음 미저장 | "통화 음성은 저장하지 않아요. 텍스트 요약만 남습니다." |
| AI 자기고지 | "통화 시작에 AI가 안내 전화를 드린다고 먼저 밝혀요." |
| 언제든 해지 | "약정도 위약금도 없어요. 언제든 끄실 수 있습니다." |

## 4. 카피 수정 (리서치 반영 — 필수)

### 4-1. "대신" 프레이밍 제거
현 히어로 "전화 한 통으로 **대신 챙겨 드려요**" / "저희가 **대신** 안부 전화를 걸어" 는 MARKETING-PLAN §2 금지 항목("자녀를 대신/대체" → "보완")에 정면으로 걸린다(inTouch 역풍 근거).

- 홈 히어로(권장): **"부모님의 하루는 그대로, 확인은 저희가"**
- 서비스 히어로(권장): **"매일 챙기고 싶은 마음은 그대로, 확인 전화만 맡겨 주세요"**
- 서브카피에서 "대신"이라는 단어 자체를 쓰지 않는다. 대체어: "함께", "거들어", "맡아".

### 4-2. AI 자기고지 (신규 FAQ 문답 + 배지)
> **Q. 사람이 직접 전화하나요?**
> A. AI 안내원이 전화를 드립니다. 통화가 시작될 때 부모님께 "자동 안내 전화"라는 점을 먼저 말씀드리고, 부모님이 편하게 답하시면 그 내용을 정리해 보호자님께 전해 드립니다. 사람이 통화를 엿듣거나 녹음을 보관하지 않습니다.

### 4-3. 119 대체 아님 고지 (THIRD-PLAN P0-7)
`SiteFooter` 에 1줄 고정 추가(의료 고지 옆). 문구는 `EMERGENCY_DISCLAIMER`(`lib/contracts/report-view.ts`) 를 **import 해 단일 소스로** 쓴다.

### 4-4. 정직한 판정을 전면화
"확인이 안 되면 억지로 판단하지 않고, **'확인 필요'라고 그대로 알려드립니다.**" — 리포트 미리보기 2종과 함께. 이것이 국내외 어디에도 없는 우리 축(THIRD-PLAN §0-1)인데 현재 랜딩에 한 줄도 없다.

## 5. 지켜야 할 것 (회귀 금지)

1. **CTA 추적은 무변경.** `PreregisterButton`/`useCtaTracking` 의 이벤트 종류·session_uuid·utm 3종 전송 로직을 건드리지 않는다. 페이지가 늘어나도 **VIEW 는 `/` 와 `/service` 에서만** 보낸다(중복 집계 방지). 새 페이지의 CTA 는 기존 `PreregisterLink`(비추적) 또는 `PreregisterButton`(추적) 중 **명시적으로 선택**해 주석으로 이유를 남긴다.
2. `sitemap.ts` 에 `/service` 추가, `robots.ts` 무변경.
3. 각 페이지 `metadata`(title/description/canonical/OG) 필수. `/` 와 `/service` 의 description 을 다르게 (중복 콘텐츠 회피).
4. 기존 `/` 로 들어오던 외부 링크가 깨지지 않아야 한다 — `/` 는 계속 200이며 리다이렉트하지 않는다.
5. 디자인 토큰만 사용(하드코딩 금지), 모바일 우선.
