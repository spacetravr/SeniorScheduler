# 리포트 설계 스펙 (v1, 2026-07-28)

> 계약: `lib/contracts/report-view.ts` (ReportDigest) · `lib/contracts/notify.ts` (채널)
> 빌더: `lib/reports/digest.ts` (`buildDigest`, `renderShareText`) — **집계·판정의 유일한 소스**
> 근거: THIRD-PLAN P0-3~0-7 / docs/research/benchmark-{ux,global}.md

## 0. 설계 목표

자녀(3050)가 **3초 안에 "괜찮은지"를 알고 닫을 수 있어야 한다.** 리포트를 기능적으로 키우는 게 아니라, 읽는 데 드는 비용을 줄이는 것이 이번 재설계의 목적이다.

- 정보를 늘리지 않는다. **계층으로 접는다.**
- 정상은 조용히, 예외는 위로. (오경보 관리가 곧 제품 — 리서치 공통 결론)
- 억지 판정 금지 원칙이 표시 레이어까지 관통한다. UNCERTAIN 은 "확인 필요"로 그대로 보여 준다.
- 채널이 늘어나도 집계는 한 곳(`buildDigest`). **채널 = 렌더러만 추가.**

## 1. 3계층 정보구조

```
L0  헤드라인   "오늘은 이상 신호가 없었어요"        ← 이것만 보고 닫아도 되는 층
    서브라인   통화 3건 · 이행 3건 (100%)
    (추이)     최근 7일 스파크라인

L1  항목 한 줄  09:00  아침 혈압약        [완료]     ← 예외가 항상 위
                18:00  저녁 약          [확인 필요]
    피보호자 2인 이상이면 이름으로 묶고, 이상 신호 있는 분이 위

L2  상세(접힘)  통화 요약 1~3문장 / 기분·건강 표시 / 대화 전문 보기
                → 기본 접힘. 예외 항목만 기본 펼침.

푸터        의료 고지 + 119 대체 아님 고지 (항상 동반, 모든 채널)
```

**톤(tone)** — 헤드라인 색과 알림 발송 여부를 동시에 결정한다.

| tone | 조건 | 화면 | EXCEPTION 레벨에서 알림 |
|---|---|---|---|
| CALM | 이상 신호 0건 | 차분한 네이비/무채색, 체크 | 보내지 않음 |
| ATTENTION | 이상 신호 1건 | 테라코타 테두리 | 보내지 않음(리포트에만) |
| ALERT | 이상 2건+ 또는 MISSED 2건+ | 테라코타 배경 + `tel:` 원버튼 | 보냄 |

단발 MISSED 를 ALERT 로 올리지 않는 것이 핵심이다(THIRD-PLAN P0-4). 부재 한 번은 장 보러 나간 것일 뿐이며, 이걸 알리면 알림 피로 → 해지로 간다.

**이행률 분모에서 MISSED 제외.** 부재는 이행 실패가 아니다. 분모가 0이면 `null`(0% 로 표시 금지).

## 2. 채널별 렌더 규칙

전부 동일한 `ReportDigest` 를 입력으로 받는다.

| 채널 | 렌더러 | 범위 | 상태 |
|---|---|---|---|
| 웹(앱 리포트·대시보드) | React (`components/app`) | L0+L1+L2 전부 | 재설계 대상 |
| 이메일(주간) | `lib/reports/render/email.ts` → HTML | L0+L1, L2 는 "자세히 보기" 링크 | 신규 |
| 카톡/문자 **공유** | `renderShareText` (구현 완료) | L0 + 예외 항목만, 정상은 건수로 | 신규 UI 버튼 |
| 알림톡(예외 알림) | `lib/reports/render/alimtalk.ts` → 변수 맵 | L0 + 버튼 2개(리포트/전화 걸기) | **스텁만** (심사 후 활성) |
| PDF(월간) | — | 후속(P1-4) | 미착수 |

### 이메일 카드 규칙
- 제목: `[주간 리포트] 7월 21일 ~ 7월 27일 · 이상 신호 1건` — **성취/안도 프레이밍**, 손실 프레임 금지.
- 발송: **화요일 오전 9시 KST** (월→화 변경, 오픈율 근거). Vercel/GH cron 은 UTC 이므로 `0 0 * * 2`.
- 본문 폭 600px 고정, 인라인 스타일만(이메일 클라이언트 호환), 다크모드 무시(라이트 고정).
- 이미지·웹폰트 금지(차단 환경 대비). 색은 디자인 토큰 값을 하드코딩하되 **출처를 주석으로** 남긴다(이메일은 CSS 변수 미지원 — 유일한 하드코딩 허용 지점).
- 수신거부 링크 필수.

### 공유 텍스트 규칙
- **전사·요약 본문을 싣지 않는다.** 카톡은 재전달이 쉬워 확산 범위를 통제할 수 없다. 예외 항목의 시각·제목·상태까지만, 나머지는 링크.
- 링크는 로그인 게이트 뒤(`/app/reports`)로 보낸다. 공개 토큰 링크는 이번 범위 아님.

## 3. 알림 레벨 (설정)

`lib/contracts/notify.ts` — `ALL` / `EXCEPTION`(기본·권장) / `WEEKLY_ONLY`.
기존 boolean 3종(0008)은 유지하되 레벨이 상위 개념으로 덮는다. 마이그레이션 매핑:

- `notify_call_result=true` → `ALL`
- `notify_call_result=false, notify_missed=true` → `EXCEPTION`
- 둘 다 false → `WEEKLY_ONLY`

## 4. 확장 지점 (지금 구현하지 않되 구조로 열어 둘 것)

1. **NotifyAdapter** — 알림톡·문자·푸시가 붙을 자리. 라우터는 레벨 판정만 하고 채널을 모른다.
2. **가족 공동 열람(P2)** — `ReportDigest` 는 이미 보호자 식별자를 담지 않는다. 읽기 전용 공유가 붙어도 구조 변경 없음.
3. **PDF/월간 리포트** — `buildDigest("MONTH", …)` 가 이미 동작한다. 렌더러만 추가.
4. **기관(B2G) 대시보드** — 피보호자 묶음(`seniors[]`)이 이미 N명 구조. 테넌트 축만 위에 얹으면 된다.
